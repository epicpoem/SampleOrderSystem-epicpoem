## 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 플랫폼 | 콘솔 기반 CLI (Windows) |
| 언어 | C++17 |
| 빌드 | Visual Studio 2022 (MSVC), `.slnx` |
| 데이터 저장 | JSON (`nlohmann/json v3.11.3`) |
| 테스트 | Google Test / Google Mock |
| 인코딩 | UTF-8 with BOM (소스), CP_UTF8 (콘솔 출력) |

### 배경

주문량 급증으로 엑셀·메모장 기반 관리의 한계가 드러난 S-Semi가 시료 등록부터 출고까지 전 과정을 하나의 프로그램에서 처리할 수 있도록 개발된 시스템입니다.

### 사용자 역할

| 역할 | 담당 업무 |
|------|-----------|
| 주문 담당자 | 고객 요청을 받아 주문 생성 및 현황 관리 |
| 생산 담당자 | 시료 등록, 주문 승인/거절, 생산·출고 처리 |

## 주문 상태 흐름

```
[RESERVED]  ─── 거절 ──────────────► [REJECTED]   (모니터링 제외)
     │
    승인
     │
  재고 확인
     ├─ 재고 충분 ──► [CONFIRMED] ──► 출고 처리 ──► [RELEASE]
     │                    ▲
     └─ 재고 부족 ──► [PRODUCING] ── 생산 완료 ──┘
```

| 상태 | 의미 |
|------|------|
| RESERVED | 주문 접수 (최초 상태) |
| REJECTED | 주문 거절 |
| PRODUCING | 승인 완료, 재고 부족으로 생산 중 |
| CONFIRMED | 승인 완료, 재고 확보 — 출고 대기 |
| RELEASE | 출고 완료 (최종 상태) |

## 개발 내용

### 구현된 기능

| 메뉴 | 기능 | 주요 구현 사항 |
|------|------|---------------|
| [1] 시료 관리 | 등록 / 목록 조회 / 검색 | 중복 ID 방지, 초기 재고 0, ID·이름·수율 검색 |
| [2] 시료 주문 | 주문 접수 | ORD-YYYYMMDD-XXXX 자동 채번, 일별 순번 관리 |
| [3] 주문 승인/거절 | RESERVED 처리 | 물리적 재고 실시간 계산, 자동 CONFIRMED/PRODUCING 분기 |
| [4] 모니터링 | 현황 대시보드 | 상태별 주문 수, 시료별 재고 상태(여유/부족/고갈), 잔여율 그래프 |
| [5] 생산라인 조회 | FIFO 큐 조회 | 진행률(%), 완료 예정 시각, 대기 큐 목록 |
| [6] 출고 처리 | CONFIRMED → RELEASE | 재고 차감, 처리 일시 기록 |
| [0] 종료 | 데이터 저장 후 종료 | JSON 자동 저장 |

### 핵심 정책

**물리적 재고 실시간 계산**
```
물리적 재고 = 보유 재고 + Σ(실생산량 × min(1.0, 경과시간 / 총생산시간))
```
메뉴 진입 시마다 PRODUCING 주문의 진행분이 비례 계산되어 재고에 반영됩니다.

**생산량 계산 (재고 부족 시)**
```
부족분     = 주문 수량 - 물리적 재고(실시간)
실 생산량  = ceil(부족분 / (수율 × 0.9))
총 생산시간 = 평균 생산시간(min/ea) × 실 생산량
```

**재고 차감 시점**

| 시점 | 처리 |
|------|------|
| CONFIRMED 전환 시 | 차감 없음 |
| PRODUCING 진행 중 | 진행분 비례로 물리적 재고에 실시간 반영 |
| RELEASE 처리 시 | 주문 수량만큼 물리적 재고에서 차감 |

## 아키텍처

```
SampleOrderSystem/
├── model/              # 도메인 엔티티 (Sample, Order, OrderStatus)
├── controller/         # 입력 처리 및 흐름 제어
│   ├── SampleController
│   ├── OrderController
│   ├── ApprovalController
│   ├── MonitorController
│   ├── ProductionController
│   └── ReleaseController
├── view/               # 콘솔 출력 전담 (인터페이스 + 구현체)
├── repository/         # 저장소 인터페이스 + JSON 구현체
│   ├── ISampleRepository / JsonSampleRepository
│   └── IOrderRepository  / JsonOrderRepository
├── service/
│   └── StockService    # 물리적 재고 계산 및 생산 완료 감지
└── util/
    ├── IClock / SystemClock   # 실제 환경 시간
    └── FakeClock              # 테스트 환경 시간 고정

SampleOrderSystemTest/
└── unit/               # 단위 테스트 (컨트롤러·리포지토리별)

data/
├── samples.json        # 시료 데이터
└── orders.json         # 주문 데이터
```

**설계 원칙**
- MVC 3계층 분리 (모델/뷰/컨트롤러)
- Repository 인터페이스와 JSON 구현체 분리 → 저장소 교체 용이
- `IClock` 추상화 → `SystemClock`(실 환경) / `FakeClock`(테스트) 주입
- View에 `ostream` 주입 → 단위 테스트에서 출력 검증 가능

## 사용법

### 빌드 환경

- Visual Studio 2022 (MSVC)
- Windows 10/11 (x64)

### 빌드 및 실행

1. `SampleOrderSystem/SampleOrderSystem.slnx` 를 Visual Studio에서 열기
2. 구성: **Debug | x64** 선택
3. `SampleOrderSystem` 프로젝트 빌드 (Ctrl+Shift+B)
4. 실행 (F5 또는 Ctrl+F5)

> 실행 파일은 `SampleOrderSystem/x64/Debug/SampleOrderSystem.exe` 에 생성됩니다.
> `data/` 폴더는 프로젝트 루트에 자동 생성됩니다.

### 메뉴 사용 흐름

```
[메인 메뉴]
  [1] 시료 관리    → 시료 등록 후 주문 가능
  [2] 시료 주문    → 등록된 시료 ID로 주문 접수 (RESERVED 생성)
  [3] 주문 승인/거절 → RESERVED 목록 확인 후 승인/거절
  [4] 모니터링     → 상태별 주문 수 및 시료별 재고 현황 확인
  [5] 생산라인 조회 → 진행률 및 대기 큐 확인
  [6] 출고 처리    → CONFIRMED 주문 출고 → RELEASE 전환
  [0] 종료         → 데이터 저장 후 종료
```

**입력 규칙**

| 상황 | 동작 |
|------|------|
| 빈 입력 | 취소 확인 메시지 → Y: 상위 메뉴 복귀 / N: 재입력 |
| 유효하지 않은 값 | 오류 안내 후 재입력 유도 |
| 숫자 필드에 문자 | 유효성 오류 안내 후 재입력 유도 |

2. 테스트 탐색기(Test Explorer)에서 전체 실행 또는 실행 파일 직접 실행

### 테스트 구성

| 테스트 파일 | 대상 | TC 수 |
|-------------|------|-------|
| SampleControllerTest | 시료 등록/조회/검색, 경계값/예외 입력 | 21개 |
| JsonSampleRepositoryTest | JSON CRUD, 파일 손상, 재고 차감 | 17개 |
| OrderControllerTest | 주문 접수, 취소, 채번, 경계값 | 18개 |
| JsonOrderRepositoryTest | 주문 CRUD, 상태별 조회, 채번 | 14개 |
| ApprovalControllerTest | 재고 계산, 상태 전이, 생산완료 감지 | 18개 |
| MonitorControllerTest | 주문 집계, 재고 상태, 물리적 재고 반영 | 17개 |

| ReleaseControllerTest | 출고 흐름, 재고 차감, Negative | 9개 |
| **합계** | | **130개** |

### 테스트 전략

- **`FakeClock`** 주입으로 생산 완료, 진행률 계산 등 시간 의존 로직을 결정적으로 검증
- **`InMemorySampleRepository`** 활용으로 컨트롤러 단위 테스트 파일 I/O 없이 격리
- **`MockRepository`** (Google Mock) 활용으로 컨트롤러-뷰 상호작용 검증
- Positive TC + Negative TC (경계값, 잘못된 입력, 파일 손상) 각 기능별 구성
