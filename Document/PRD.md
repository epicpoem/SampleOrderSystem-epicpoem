# PRD - 반도체 시료 생산주문관리 시스템

## 1. 제품 개요

가상의 반도체 회사 "S-Semi"는 실리콘 웨이퍼, GaN 에피택셜 등 다양한 반도체 시료를 생산하여 연구소, 팹리스 업체, 대학 연구실 등에 납품한다. 주문량 급증으로 엑셀/메모장 기반 관리의 한계가 드러나, 주문·생산·출고를 하나의 콘솔 프로그램에서 관리할 수 있는 시스템이 필요하다.

## 2. 사용자 및 역할

| 역할 | 설명 |
|------|------|
| 주문 담당자 | 고객 요청을 받아 주문을 생성하고 주문 현황을 관리한다 |
| 생산 담당자 | 시료를 등록하고, 접수된 주문을 승인 또는 거절하며 생산·출고를 처리한다 |

## 3. 사용자 요구사항

### 3-1. 시료 관리

- 사용자는 새로운 시료를 시스템에 등록할 수 있어야 한다.
  - 등록 시 시료 ID, 이름, 평균 생산시간(min/ea), 수율을 입력한다.
  - 이미 등록된 시료 ID를 입력하면 등록이 거부되어야 한다.
  - 등록 직후 초기 재고는 0으로 설정된다.
- 사용자는 등록된 모든 시료 목록을 현재 재고 수량과 함께 조회할 수 있어야 한다.
- 사용자는 시료 ID, 이름, 수율 등 속성을 선택하여 특정 시료를 검색할 수 있어야 한다.

### 3-2. 시료 주문

- 사용자는 고객의 요청에 따라 시료 주문을 접수할 수 있어야 한다.
  - 접수 시 시료 ID, 고객명, 주문 수량을 입력한다.
  - 접수된 주문에는 날짜 기반 고유 주문번호(ORD-YYYYMMDD-XXXX)가 자동 부여된다.
  - 접수 직후 주문 상태는 "예약(RESERVED)"으로 설정된다.
- 주문 접수 시점에는 재고를 확인하지 않는다. 재고 확인은 승인 처리 단계에서 이루어진다.

### 3-3. 주문 승인/거절

- 사용자는 예약(RESERVED) 상태의 주문 목록을 확인할 수 있어야 한다.
- 사용자는 특정 주문을 승인하거나 거절할 수 있어야 한다.
- 주문을 거절하면 해당 주문은 "거절(REJECTED)" 상태로 전환되어야 한다.
- 주문을 승인하면 현재 물리적 재고를 기준으로 처리 방식이 자동으로 결정되어야 한다.
  - 물리적 재고가 주문 수량 이상이면 즉시 "출고 대기(CONFIRMED)" 상태로 전환된다.
  - 물리적 재고가 부족하면 생산 라인에 자동 등록되어 "생산 중(PRODUCING)" 상태로 전환된다.
- 재고 부족 시 사용자는 부족분, 실제 생산량, 예상 생산 소요 시간을 확인한 뒤 최종 승인 여부를 결정할 수 있어야 한다.
- 물리적 재고 계산에는 현재 생산 중인 주문의 시간 비례 예정 입고 수량이 포함된다.

### 3-4. 모니터링

- 사용자는 상태별(예약/확정/생산중/출고완료) 주문 건수를 한눈에 확인할 수 있어야 한다.
  - 거절된 주문은 모니터링 집계에서 제외된다.
- 사용자는 시료별 현재 재고 수량과 재고 상태를 확인할 수 있어야 한다.
  - 재고 상태는 "여유", "부족", "고갈" 세 가지로 표기된다.
  - 재고 상태 판단 기준은 확정(CONFIRMED)과 생산중(PRODUCING) 주문의 총 주문량이다.

### 3-5. 생산라인 조회

- 사용자는 현재 생산 중인 주문의 진행 상황을 확인할 수 있어야 한다.
  - 주문번호, 시료명, 주문량, 실생산량, 현재 진행률(%), 완료 예정 일시를 표시한다.
- 사용자는 생산 대기 중인 주문 목록을 FIFO 순서로 확인할 수 있어야 한다.
- 화면은 사용자가 해당 메뉴에 진입하는 시점에 최신 상태로 계산되어 표시된다.
- 생산이 완료된 주문은 자동으로 "출고 대기(CONFIRMED)" 상태로 전환된다.

### 3-6. 출고 처리

- 사용자는 출고 대기(CONFIRMED) 상태의 주문 목록을 확인할 수 있어야 한다.
- 사용자는 특정 주문을 선택하여 출고 처리를 실행할 수 있어야 한다.
  - 출고 처리 후 주문 상태는 "출고 완료(RELEASE)"로 전환된다.
  - 출고 수량만큼 해당 시료의 재고에서 차감된다.

### 3-7. 데이터 영속성

- 시스템을 종료해도 등록된 시료 정보, 주문 이력, 생산 이력이 유지되어야 한다.
- 시스템을 재시작하면 이전에 저장된 데이터를 그대로 불러올 수 있어야 한다.

### 3-8. 메인 화면

- 사용자는 시스템 진입 시 현황 요약(등록 시료 수, 총 재고, 전체 주문 수, 생산라인 대기 건수)을 확인할 수 있어야 한다.

## 4. 비기능 요구사항

- 콘솔(CLI) 환경에서 동작한다.
- 한글이 깨지지 않고 정상 출력되어야 한다.
- 생산 진행 상태는 별도의 백그라운드 스레드 없이, 메뉴 진입 시 경과 시간을 계산하는 방식으로 처리한다.
- 테스트 시 시간을 임의로 제어할 수 있는 구조(Clock 추상화)를 갖춰야 한다.

## 5. 주문 상태 전이 요약

```
[RESERVED]
    ├─ 거절 → [REJECTED]       (모니터링 제외)
    └─ 승인 → 재고 확인
               ├─ 충분 → [CONFIRMED] → 출고처리 → [RELEASE]
               └─ 부족 → [PRODUCING] → 생산완료 → [CONFIRMED] → 출고처리 → [RELEASE]
```
